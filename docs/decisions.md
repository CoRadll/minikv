## D-001 源文件强制 UTF-8，MSVC 显式加 `/utf-8`

**背景**：源码含中文注释，文件编码为 UTF-8。

**问题**：MSVC 默认按系统代码页（简体中文环境为 936/GBK）解析源文件。
UTF-8 的中文字节被按 GBK 解码后，若某个字节被解释为行尾反斜杠，会触发行续接，
把下一行声明吞进注释里。表现不是「编码错误」，而是诸如
`error C2039: "kProjectName" 不是 "minikv" 的成员` 的幻影错误，极难定位。

**决定**：CMake 中统一 `add_compile_options(/utf-8)`；编辑器侧固定
`files.encoding = utf8`、关闭 `autoGuessEncoding`。

**后果**：
- 干净构建 0 warning（曾经每条 C4819 都是潜在的数据损坏）
- 跨机器协作不依赖本地代码页，Linux/macOS 下行为一致
- `/utf-8` 同时等价于 `/source-charset:utf-8 /execution-charset:utf-8`，
  不可与二者重复叠加，否则报 `D8016`

## D-002 全项目不使用异常，错误通过 `Status` 返回值传递

**背景**：存储引擎的失败路径很多且必须被处理（IO 失败、CRC 不匹配、文件截断）。

**问题**：异常会隐藏控制流。在「把数据写进文件」这类代码里，
一个未捕获异常跑到析构链里，可能导致半写状态或静默丢数据。

**决定**：
- 所有可能失败的函数返回 `Status`，成功为 `ok()`
- 内存分配失败按致命错误处理，不做逐处捕获
- 不使用 `throw` / `try` / `catch`

**后果**：
- 失败路径在调用处显式可见，编译器也能提醒忽略返回值
- 与 RAII 配合良好：资源释放走析构，错误传播走返回值
- 代价是代码略啰嗦，需要在每层做 `if (!s.ok()) return s;`

**替代方案**：`std::expected`。C++23 才标准化，MSVC 19.34 支持不完整，暂不采用。

## D-003 `include/` 与 `src/` 逐文件同构，`api/` 为公开门面

**背景**：头文件与实现如果自由摆放，项目长大后会出现
「头文件在 A 目录、实现散在 B/C/D」的情况，重构成本极高。

**问题**：如何让「改一个文件」的波及范围可预测。

**决定**：
- 有 `.cc` 的头文件，必须在 `include/minikv/` 下有一条**完全相同的相对路径**
- 纯定义 / 纯虚接口允许只有头文件，登记在例外名单
- 对外门面收敛到 `include/minikv/api/`，内部头不对外承诺稳定

**后果**：
- 找文件只需一次路径映射，重构可批量机械替换
- 规则由 `scripts/check_layout.ps1` 校验，不依赖人工记忆
- 例外需要显式登记，避免「特例悄悄扩散」

## D-004 阶段制推进（S0–S5），按验收标准而非日历排期

**背景**：投入时间不固定，可能出现「一周 20 小时、接下来一周 2 小时」的波动。

**问题**：按周排期会不断过期，且无法判断「做到哪算够」。

**决定**：
- 以「可验收的产出」为阶段边界，每个阶段结束都是可停下的点
- 每个阶段有明确的完成判据（可执行命令 + 预期输出）
- 不设截止日期，只设依赖关系

**后果**：
- 任意阶段暂停都有可交付物，不存在「做到一半什么都没有」
- 里程碑与简历叙事对齐：S2 可写、S3 完整、S5 有量化数据
