# 阶段演示规格（demo）

每个阶段交付一个**可执行、确定性、自带断言**的演示命令，用来证明「这一阶段真的做完了且能用」。

## 1. 通用约定

### 调用方式

```powershell
.\build\bin\Debug\minikv.exe demo s1 --dir .\demo-data\s1
```

| 参数 | 说明 |
|---|---|
| `s1` … `s5` | 演示某一阶段的能力 |
| `all` | 从 s1 到当前已完成的阶段依次执行 |
| `--dir <path>` | 数据目录，演示开始前会被清空 |

### 输出要求

1. **确定性**：除耗时外，所有行都是固定文本；同一版本重复执行输出逐字节一致
2. **行为断言只用公开接口**：通过 `Engine::Put/Get/Delete` 验证；日志与文件展示可以复用
   内部编解码函数（如 `wal/wal_format.h`），但**不读取类内部状态**，否则演示的是实现细节
3. **带断言**：每一步比对期望值，不符立即打印 `FAIL: <原因>` 并以退出码 1 结束
4. **落盘**：transcript 同时写入 `demo/sN-transcript.txt`（控制台与文件内容一致）

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 全部步骤通过 |
| 1 | 某一步断言失败 |
| 2 | 运行环境问题（目录不可写、构建缺失等） |

### 验收挂钩

阶段完成判据新增一条：

> `minikv.exe demo sN` 退出码 0，且 `demo/sN-transcript.txt` 已生成。

## 2. S1：WAL + MemTable + 崩溃恢复

**证明目标**：写入可持久化、删除语义正确、重启能回放、坏尾能安全截断。

| 步骤 | 动作 | 断言 |
|---|---|---|
| 1 | 在空目录打开引擎 | WAL 文件被创建，大小 0 |
| 2 | `put user:1 张三`、`put user:2 李四`、`put counter 42` | 三次返回 OK；WAL 大小 > 0 |
| 3 | 逐条解码 WAL 并打印（类型 / key 长度 / value 长度 / CRC / key） | 记录数 = 3，CRC 全部通过 |
| 4 | 读取三个 key | 值与写入一致 |
| 5 | `del user:2` 后再读 | 返回 NotFound；WAL 大小增加 |
| 6 | 不调用 `Close`，直接丢弃引擎对象（模拟崩溃） | — |
| 7 | 重新打开同一目录 | 回放记录数 = 4；三个 `get` 结果与崩溃前一致（含删除） |
| 8 | 向 WAL 尾部追加 7 个垃圾字节，再次打开 | 报告丢弃 7 字节；数据仍可读；WAL 大小被截断回有效长度 |

**展示的工程价值**：第 3 步把二进制日志翻译成人能看懂的表格，第 8 步把「断电写了半条记录」这件事变成可复现实验。

## 3. S2：SSTable 落盘与加载

**证明目标**：内存阈值触发刷盘、数据以 SSTable 形式存活、重启从文件加载。

| 步骤 | 动作 | 断言 |
|---|---|---|
| 1 | 用极小阈值（如 4KB）打开引擎 | 阈值生效 |
| 2 | 写入 2000 条 | 过程中产生 ≥ 1 个 `.sst` 文件 |
| 3 | 列出数据目录并打印每个 SSTable 的大小 | 文件数 > 0，总大小与写入量同量级 |
| 4 | 关闭并重新打开 | 从 SSTable 加载成功 |
| 5 | 随机抽 20 个 key 读回 | 全部命中且值正确 |
| 6 | 打印 `stats`（文件数、各层文件数） | 与目录实际文件一致 |

---

## 4. S3：Compaction

**证明目标**：文件数收敛、旧版本被清理、删除的数据不会复活。

| 步骤 | 动作 | 断言 |
|---|---|---|
| 1 | 小阈值写入 10000 条 | 触发多次刷盘 |
| 2 | 打印 compaction 前的文件数与总大小 | — |
| 3 | 对同一批 key 覆盖写 10000 次 | 产生大量旧版本 |
| 4 | 手动触发 compaction（或等待完成） | 文件数下降 |
| 5 | 打印 compaction 后的文件数与总大小 | 总大小显著下降 |
| 6 | 删除若干 key 后再次 compaction | 被删 key 读回 NotFound |

---

## 5. S4：布隆过滤器与块缓存

**证明目标**：不存在的 key 不产生数据块读取。

| 步骤 | 动作 | 断言 |
|---|---|---|
| 1 | 写入 5000 条并刷盘 | 生成若干 SSTable |
| 2 | 查询 1000 个**不存在**的 key | 全部 NotFound |
| 3 | 打印块缓存统计（命中 / 未命中 / 读取块数） | 实际读取块数 ≈ 0（远小于文件数 × 1000） |
| 4 | 关闭布隆过滤器（开关）对比 | 读取块数显著上升 |
| 5 | `scan` 一个前缀范围 | 结果有序且完整 |

---

## 6. S5：崩溃测试与量化

**证明目标**：真实进程被强杀后已确认写入不丢；给出可写进简历的数字。

| 步骤 | 动作 | 断言 |
|---|---|---|
| 1 | 启动子进程，写入并逐条确认 | — |
| 2 | 对子进程执行 `kill -9`（Windows 用 `TerminateProcess`） | 进程非正常退出 |
| 3 | 重新打开数据库 | 已确认的写入全部可读 |
| 4 | 基准测试：顺序写 / 随机读 / 混合 | 输出吞吐与 P50/P99/P999 |
| 5 | 打印数据规模、文件数、恢复耗时 | 形成可引用的结果表 |

---

## 7. transcript 的使用方式

| 用途 | 做法 |
|---|---|
| 阶段验收 | 人工扫一眼 + 退出码 0 |
| 回归 | 关键行做文本断言（后续可加） |
| 面试演示 | 现场执行 `demo s1`，30 秒讲完一个阶段 |
| README 证据 | 挑选一次 transcript 手工复制到 `docs/`，或截图 |

运行产物（`demo-data/`、`demo/*.txt`）默认被 `.gitignore` 忽略。
